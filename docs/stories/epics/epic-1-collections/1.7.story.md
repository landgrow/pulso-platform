# Story 1.7 — UI: Visualização Consolidada do Período

**Épico:** Épico 1 — Motor de Coleções
**Status:** ✅ Concluída (05/09/2026)
**Story Points:** 5 (M)
**Depende de:** Stories 1.3, 1.4, 1.5, 1.6

## Descrição

Construir a vista unificada de um período: cards por fonte (Formulário, Uploads, Texto, Áudio), status badge, botão "Marcar como pronto para análise", e timeline de revisões resumida.

```typescript
// src/components/collections/periodo/status-badge.tsx
import { Badge } from "@/components/ui/badge";
import { Lock, CircleCheck, CircleDashed, CircleDot } from "lucide-react";

const STATUS_CONFIG = {
  em_coleta: {
    label: "Em coleta",
    variant: "secondary" as const,
    icon: CircleDashed,
    className: "bg-yellow-100 text-yellow-800",
  },
  pronto_para_analise: {
    label: "Pronto p/ análise",
    variant: "default" as const,
    icon: CircleDot,
    className: "bg-blue-100 text-blue-800",
  },
  analisado: {
    label: "Analisado",
    variant: "default" as const,
    icon: CircleCheck,
    className: "bg-green-100 text-green-800",
  },
  fechado: {
    label: "Fechado",
    variant: "outline" as const,
    icon: Lock,
    className: "bg-gray-100 text-gray-600",
  },
};

export function StatusBadge({ status, closedAt }: { status: PeriodStatus; closedAt?: string | null }) {
  const config = STATUS_CONFIG[status];
  const Icon = config.icon;
  return (
    <Badge variant={config.variant} className={config.className}>
      <Icon className="size-3" />
      {config.label}
      {closedAt && status === "fechado" && (
        <span className="ml-1 text-xs opacity-70">
          {new Date(closedAt).toLocaleDateString("pt-BR")}
        </span>
      )}
    </Badge>
  );
}
```

### Server action `markReadyForAnalysis`

```typescript
// src/app/actions/periodo-status.ts
"use server";

import { z } from "zod";
import { createClient } from "@/lib/supabase/server";

const markReadySchema = z.object({
  periodId: z.string().uuid(),
});

export async function markReadyForAnalysis(input: unknown): Promise<Result<{ status: string }>> {
  const parsed = markReadySchema.parse(input);
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return { success: false, error: "Not authenticated", code: "PERMISSION_DENIED" };

  // Verifica status atual
  const { data: periodo } = await supabase
    .from("periodos_dados")
    .select("id, status, cliente_id")
    .eq("id", parsed.periodId)
    .single();

  if (!periodo) return { success: false, error: "Não encontrado", code: "NOT_FOUND" };
  if (periodo.status !== "em_coleta") {
    return { success: false, error: "Período não está em coleta", code: "INVALID_INPUT" };
  }

  // Contagem de fontes
  const { count: colecoesCount } = await supabase
    .from("colecoes")
    .select("id", { count: "exact", head: true })
    .eq("periodo_id", parsed.periodId)
    .neq("status", "descartado");

  const { count: evidenciasCount } = await supabase
    .from("evidencias")
    .select("id", { count: "exact", head: true })
    .eq("periodo_id", parsed.periodId);

  const hasContent = (colecoesCount ?? 0) > 0 || (evidenciasCount ?? 0) > 0;

  // Verifica permissão: client_member pode se houver conteúdo, ou client_owner pode override
  const role = await getActiveOrgRole(supabase);
  if (!hasContent && role !== "client_owner" && !await isPlatformAdmin()) {
    return {
      success: false,
      error: "Adicione pelo menos 1 coleção ou evidência antes de marcar como pronto",
      code: "INVALID_INPUT",
    };
  }

  const { error } = await supabase
    .from("periodos_dados")
    .update({ status: "pronto_para_analise", updated_at: new Date().toISOString() })
    .eq("id", parsed.periodId);

  if (error) return { success: false, error: error.message, code: "INTERNAL_ERROR" };

  await logAudit(supabase, /* org_id */, "mark_ready", "periodo_dados", parsed.periodId, {
    colecoes: colecoesCount,
    evidencias: evidenciasCount,
  });

  return { success: true, data: { status: "pronto_para_analise" } };
}
```

## Change Log

### Implementação (05/09/2026)

**`markReadyForAnalysis` como action nova, não reaproveitando `updatePeriodData`:** `updatePeriodData` (Story 1.2, em `periods.ts`) já existe e já sabe mudar `status`, mas é uma action genérica de edição de campo — não sabe nada sobre a regra de negócio "formulário 100% + 1 fonte" nem precisa gravar um audit log com esse nome/metadata específico. Criar `markReadyForAnalysis` como uma action própria (duplicando as ~10 linhas de checagem de permissão/status, no mesmo estilo que `discardColecao`/`restoreColecao`/`deleteColecao` já duplicam entre si) manteve o audit log legível (`action = "mark_ready"` com contagens) em vez de um `action = "update"` genérico.

**Reaproveitado `FileList` (Story 1.4) para a lista de evidências (AC-4):** em vez de reescrever a tabela do zero, um wrapper fino (`lista-evidencias-periodo.tsx`) só dá a ela estado local nesta página. Isso significa que "filtro por tipo" e "ordenação por data" da AC-4 não foram implementados — `FileList` não tem essas duas opções e adicionar UI de filtro/ordenação nela impactaria também a página de upload (Story 1.4) sem pedido explícito para isso. Fica como próximo incremento se a Nayara quiser.

**Página nova fora do plano — `/clientes/[slug]` (lista de períodos):** a AC-6 pede um "Botão Voltar para lista de períodos", mas essa página nunca existia — na verdade, o link "‹ Nome do cliente" no breadcrumb de TODAS as páginas de coleta desde a Story 1.3 apontava pra uma rota inexistente (404). A action `listPeriods` (Story 1.2) já existia pronta pra isso, só nunca tinha sido consumida por nenhuma UI. Construída aqui porque (a) é pequena, (b) fecha a AC-6 desta story de verdade, e (c) conserta retroativamente a navegação quebrada de 4 stories anteriores de graça.

**Bug de infraestrutura de dev encontrado e corrigido:** `.claude/launch.json` apontava para `npx serve -l 8080 .` — um servidor estático servindo a raiz do projeto, sobra de uma versão anterior (pré-Next.js) deste mesmo projeto. Isso significa que o preview/dev-server configurado nunca rodou a aplicação Next.js de verdade em nenhuma sessão anterior. Corrigido para rodar `npm run dev` na porta 3000.

**Verificação visual — limitação:** com o dev server corrigido, consegui confirmar que as rotas novas (`/clientes/[slug]` e `/clientes/[slug]/periodo/[id]`) carregam sem erro 500 e redirecionam corretamente pra tela de login quando não autenticado (sem stack trace nos logs do servidor). Não fiz uma verificação visual autenticada da página completa (cards, badge, botão, listas) porque não existe usuário/organização de teste neste projeto, e criar uma conta nova está fora do que posso fazer sem autorização explícita da Nayara em cada caso. Fica pro checklist manual dela quando for revisar.
