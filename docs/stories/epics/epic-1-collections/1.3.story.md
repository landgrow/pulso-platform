## Descrição

Construir a UI de coleta via formulário estruturado: 12 perguntas (mesmas do PRD v1.0 seção 5.1) organizadas por área de análise (Financeiro, Operacional, Comercial, Pessoas, Estratégico, Marketing). Auto-save por campo com debounce de 1.5s. Indicador de progresso visual.

### Hook `useAutoSave`

```typescript
// src/hooks/use-auto-save.ts
export function useAutoSave<T>({
  onSave,
  debounceMs = 1500,
}: {
  onSave: (value: T) => Promise<void>;
  debounceMs?: number;
}) {
  const [status, setStatus] = useState<
    "idle" | "dirty" | "saving" | "saved" | "error"
  >("idle");
  const valueRef = useRef<T | null>(null);
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  const save = useCallback(
    (value: T) => {
      valueRef.current = value;
      setStatus("dirty");
      if (timerRef.current) clearTimeout(timerRef.current);
      timerRef.current = setTimeout(async () => {
        if (valueRef.current === null) return;
        setStatus("saving");
        try {
          await onSave(valueRef.current);
          setStatus("saved");
        } catch {
          setStatus("error");
        }
      }, debounceMs);
    },
    [onSave, debounceMs],
  );

  return { save, status };
}
```

### Server action `updateColecao`

```typescript
// src/app/actions/colecoes.ts
const upsertColecaoSchema = z.object({
  periodoId: z.string().uuid(),
  tipo: z.enum(["formulario", "texto_livre", "transcricao_audio"]),
  payload: z.record(z.unknown()),
  metadata: z.record(z.unknown()).optional(),
});

export async function upsertColecao(
  input: unknown,
): Promise<Result<{ colecaoId: string }>> {
  const parsed = upsertColecaoSchema.parse(input);
  const supabase = await createClient();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user)
    return {
      success: false,
      error: "Not authenticated",
      code: "PERMISSION_DENIED",
    };

  // Verifica se período está fechado
  const { data: periodo } = await supabase
    .from("periodos_dados")
    .select("status")
    .eq("id", parsed.periodoId)
    .single();

  if (periodo?.status === "fechado") {
    return { success: false, error: "Período fechado", code: "PERIOD_CLOSED" };
  }

  // Upsert (1 coleção por (periodo_id, tipo))
  const { data, error } = await supabase
    .from("colecoes")
    .upsert(
      {
        periodo_id: parsed.periodoId,
        tipo: parsed.tipo,
        payload: parsed.payload,
        metadata: parsed.metadata ?? {},
        created_by: user.id,
        updated_at: new Date().toISOString(),
      },
      { onConflict: "periodo_id,tipo" },
    )
    .select("id")
    .single();

  if (error)
    return { success: false, error: error.message, code: "INTERNAL_ERROR" };
  return { success: true, data: { colecaoId: data.id } };
}
```

## Change Log

**05/09/2026 — retomada após o Cursor ficar sem créditos no meio desta story.**

Estado encontrado: quase todos os arquivos do File List já existiam no disco, mas a story ainda
constava como "⏳ Pendente" com checklist vazio — os documentos de tracking nunca foram
atualizados, e os gates nunca tinham sido rodados de verdade.

Rodei `npm run typecheck` para confirmar o estado real e encontrei **11 erros reais**, todos
corrigidos:

1. **Dois sistemas de toast coexistindo** — o app inteiro usa `sonner` (7 arquivos + `<Toaster>`
   real montado no layout), mas sobrou um hook shadcn/Radix (`src/hooks/use-toast.ts` +
   `src/components/ui/toast.tsx`) nunca conectado a nada, quebrado e morto. **Removidos os dois
   arquivos.**
2. `formulario-client.tsx` chamava `toast({ title, description, variant })` — essa é a API do
   shadcn, não do sonner. Corrigido para `toast.error(msg, { description })` /
   `toast.success(msg, { description })`. Também tirei `toast` do array de dependências do
   `useCallback` (import de módulo, não precisa estar lá).
3. `page.tsx` acessava `periodDetail.data.period.status`, que não existe no tipo `PeriodDetail`
   (o campo aninhado é `periodo`, não `period`). Corrigido para usar `periodDetail.data.period.canEdit`,
   que já existe e já encapsula a mesma regra (fechado/analisado + papel do usuário) sem duplicar
   lógica no cliente.
4. `form-field.tsx`: import não usado de `RadioGroupItem` (o radio é HTML nativo, não usa esse
   componente) — removido. Tipo `error?: string` endurecido para `error?: string | undefined`
   (exigência do `exactOptionalPropertyTypes`).
5. `colecoes.ts`: 2 `@ts-expect-error` sobrando que não suprimiam mais nada — removidos.

**Bug real encontrado só depois, ao escrever os testes (não pelo typecheck):**

6. **`buildFormularioSchema()` quebrava sempre que era chamada** — `.refine()` nos campos
   radio/select devolve `ZodEffects`, que não tem `.min()`, e o código tentava chamar
   `(field as z.ZodString).min(1, ...)` nesse tipo. Por isso a validação Zod nunca esteve
   realmente conectada em lugar nenhum do app — ninguém nunca tinha chamado a função com sucesso.
   Corrigido trocando `.min()` por `.refine()` (funciona em ambos os tipos).
7. **Campos numéricos opcionais não eram realmente opcionais** — o `z.union([...])` de
   "aceita vazio ou número" nunca tinha `.optional()` aplicado, então omitir o campo inteiro
   (o caso normal de "não preencheu") falhava a validação. Corrigido acrescentando `.optional()`
   ao final da união.

Ambos os bugs 6 e 7 só apareceram ao escrever os 18 testes do schema — reforça por que a AC-6
não é opcional.

**Achado à parte, fora do escopo desta story:** ao rodar a suíte e2e completa pela primeira vez
(os browsers do Playwright nunca tinham sido instalados neste ambiente), 4 testes de
`public-pages.spec.ts` (Épico 0 — privacy, terms, register, forgot-password) falharam. Não são
