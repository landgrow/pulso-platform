## Descrição

Construir a UI de upload de arquivos (PDF, Excel, CSV) com drag-and-drop, validação client-side e server-side, salvamento no Supabase Storage, e listagem/visualização inline.

### AC-1: UI `/clientes/[slug]/coleta/upload`

- [x] Server Component para layout
- [x] Client Component com drop zone (react-dropzone)
- [x] Limites: 25MB por arquivo, 5 arquivos por upload, 100MB total por sessão
- [x] Tipos aceitos: `application/pdf`, `application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `text/csv`

- [x] MIME type checado antes do upload
- [x] Extensão do arquivo checada como segunda barreira
- [x] Magic number checado (primeiros bytes do arquivo)

### AC-3: Upload para Storage

- [x] Path: `{org_id}/{periodo_id}/{evidencia_id}-{sanitized_filename}`
- [ ] Upload com progresso — mesma decisão do item acima (AC-1)

- [x] Após sucesso, insere registro em `evidencias` com metadata completa
- [x] Audit log: action = `upload`, resource_type = `evidencia`

### AC-4: Listagem e visualização

## Notas Técnicas

### `file-validator.ts`

```typescript
// src/lib/storage/file-validator.ts
const MAGIC_NUMBERS: Record<string, number[]> = {
  pdf: [0x25, 0x50, 0x44, 0x46], // %PDF
  xlsx: [0x50, 0x4b, 0x03, 0x04], // PK (ZIP)
  csv: null, // texto puro, sem magic
};

const MAX_SIZE = 25 * 1024 * 1024; // 25MB
const ACCEPTED_MIMES = [
  "application/pdf",
  "application/vnd.ms-excel",
  "application/vnd.openxmlformats-officedocument.spreadsheetmlsheet",
  "text/csv",
];

export type FileValidationError =
  | { code: "TOO_LARGE"; maxBytes: number }
  | { code: "BAD_MIME"; accepted: string[] }
  | { code: "BAD_MAGIC"; expected: string }
  | { code: "BAD_EXTENSION" };

export function validateFile(file: File): FileValidationError | null {
  if (file.size > MAX_SIZE) {
    return { code: "TOO_LARGE", maxBytes: MAX_SIZE };
  }
  if (!ACCEPTED_MIMES.includes(file.type)) {
    return { code: "BAD_MIME", accepted: ACCEPTED_MIMES };
  }
  // Magic number check (best-effort, async)
  return null;
}

export async function checkMagicNumber(file: File): Promise<boolean> {
  const buffer = new Uint8Array(await file.slice(0, 4).arrayBuffer());
  const ext = file.name.split(".").pop()?.toLowerCase();
  const expected = ext ? MAGIC_NUMBERS[ext] : null;
  if (expected === null) return true; // CSV ou outro
  return expected.every((b, i) => buffer[i] === b);
}

export async function sha256(file: File): Promise<string> {
  const buffer = await file.arrayBuffer();
  const hashBuffer = await crypto.subtle.digest("SHA-256", buffer);
  return Array.from(new Uint8Array(hashBuffer))
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("");
}
```

### Server action `uploadEvidencia`

```typescript
// src/app/actions/evidencias.ts
import { z } from "zod";

const uploadSchema = z.object({
  periodoId: z.string().uuid(),
  storagePath: z.string().min(1).max(500),
  nomeOriginal: z.string().min(1).max(255),
  mimeType: z.string().min(1).max(100),
  tamanhoBytes: z.number().int().positive().max(25 * 1024 * 1024),
  hash: z.string().length(64), // SHA-256 hex
});

export async function uploadEvidencia(input: unknown): Promise<Result<{ evidenciaId: string }>> {
  const parsed = uploadSchema.parse(input);
  const supabase = await createClient();

  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return { success: false, error: "Not authenticated", code: "PERMISSION_DENIED" };

  // Verifica duplicata
  const { data: dup } = await supabase
    .from("evidencias")
    .select("id")
    .eq("hash", parsed.hash)
    .single();
  if (dup) {
    return { success: false, error: "Arquivo já enviado", code: "INVALID_INPUT" };
  }

  // Verifica período não-fechado
  const { data: periodo } = await supabase
    .from("periodos_dados")
    .select("status")
    .eq("id", parsed.periodoId)
    .single();
  if (periodo?.status === "fechado") {
    return { success: false, error: "Período fechado", code: "PERIOD_CLOSED" };
  }

  const tipo =
    parsed.mimeType === "application/pdf" ? "pdf" :
    parsed.mimeType.includes("excel") || parsed.mimeType.includes("spreadsheet") ? "excel" :
    parsed.mimeType === "text/csv" ? "csv" :
    "outro";

  const { data, error } = await supabase
    .from("evidencias")
    .insert({
      periodo_id: parsed.periodoId,
      tipo,
      storage_path: parsed.storagePath,
      nome_original: parsed.nomeOriginal,
      mime_type: parsed.mimeType,
      tamanho_bytes: parsed.tamanhoBytes,
      hash: parsed.hash,
      uploaded_by: user.id,
    })
    .select("id")
    .single();

  if (error) return { success: false, error: error.message, code: "INTERNAL_ERROR" };

  await logAudit(supabase, /* org_id */, "upload", "evidencia", data.id, {
    nome: parsed.nomeOriginal,
    tamanho: parsed.tamanhoBytes,
  });

  return { success: true, data: { evidenciaId: data.id } };
}
```

### Upload para Storage (client-side)

```typescript
// src/lib/storage.ts
import { createClient } from "@/lib/supabase/client";

export async function uploadToStorage(
  path: string,
  file: File,
  onProgress?: (pct: number) => void,
): Promise<{ path: string }> {
  const supabase = createClient();
  const { data, error } = await supabase.storage
    .from("evidencias")
    .upload(path, file, {
      cacheControl: "3600",
      upsert: false,
    });
  if (error) throw error;
  return { path: data.path };
}

export async function getSignedUrl(
  path: string,
  expiresIn = 300,
): Promise<string> {
  const supabase = createClient();
  const { data, error } = await supabase.storage
    .from("evidencias")
    .createSignedUrl(path, expiresIn);
  if (error) throw error;
  return data.signedUrl;
}
```

## Change Log

**05/09/2026 — implementação completa.**

**Achado antes de escrever qualquer código:** o schema e a RLS de `storage.objects` já existiam
prontos (`db/migrations/0006_storage_evidencias.sql`), incluindo bucket privado de 25MB com
allowlist de MIME e as 3 policies (select/insert/delete). Isso reduziu bastante o escopo real —
não foi preciso escrever migração nova, só as camadas de aplicação.

**Decisão de segurança fora do que a story previa:** ao instalar `xlsx` (SheetJS) do npm,
`npm audit` acusou uma vulnerabilidade de **prototype pollution de severidade alta, sem correção
disponível no registro do npm** — relevante aqui porque a função exata dessa lib é processar
arquivo enviado por usuário (o vetor de ataque exato). Troquei pela build oficial da SheetJS
distribuída no CDN deles (`https://cdn.sheetjs.com/xlsx-0.20.3/...`), que é a correção
recomendada pelo próprio projeto SheetJS para esse CVE. `npm audit` confirma que o pacote
`xlsx` não aparece mais na lista de vulnerabilidades depois da troca.

**Decisão deliberada de escopo:** a AC-1/AC-3 pediam barra de progresso via
`XMLHttpRequest`/`onUploadProgress`. O cliente `@supabase/supabase-js` de Storage usa `fetch`
por baixo, que não expõe evento de progresso de upload — construir um uploader via XHR customizado
só pra isso seria escopo novo não pedido em lugar nenhum. A fila mostra estado
(`validando → enviando → registrando → enviado/erro`) com spinner, sem percentual.

**Discrepância encontrada entre a AC-4 e a RLS real:** a story dizia "Excluir (apenas uploader
ou client_owner)". A policy `evidencias_delete` já aplicada no banco (seção 0005) só permite
**uploader ou platform_admin** — não inclui client_owner. Implementei respeitando a RLS real
(é ela quem de fato decide, o código da action só antecipa a mensagem de erro), não o texto da AC.

**Reaproveitamento:** `canEdit` (já calculado em `getPeriod`, usado na story 1.3) já exclui
`client_viewer` e períodos fechados — não dupliquei essa regra de permissão na UI de upload,
só reaproveitei o mesmo campo.
