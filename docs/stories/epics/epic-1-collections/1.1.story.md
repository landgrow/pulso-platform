## Descrição

Criar o schema do banco de dados para o motor de coleções: tabelas `clientes`, `periodos_dados`, `colecoes`, `evidencias`, todas com RLS default-deny. Esta é a fundação para todas as demais stories do épico.

### AC-2: RLS default-deny

- [ ] RLS habilitado em `clientes`, `periodos_dados`, `colecoes`, `evidencias`
- [ ] RLS FORCED em todas
- [ ] Policy SELECT: `can_access_org(org_id)` propagado via JOIN
- [ ] Policy INSERT: client_owner ou client_member da org
- [ ] Policy UPDATE: client_owner ou client_member (exceto clientes em período fechado)
- [ ] Policy DELETE: apenas platform_admin ou client_owner
- [ ] Teste SQL: `db/test-rls.sql` atualizado com 4 cenários de isolamento entre orgs

- [ ] RPC exposta via `supabase.rpc()` com `SECURITY INVOKER` (não bypassa RLS)

### AC-4: Storage bucket

- [ ] Bucket `evidencias` criado no Supabase Storage (private)
- [ ] RLS do storage: apenas membros da org podem ler/escrever
- [ ] Path convention: `{org_id}/{periodo_id}/{evidencia_id}-{filename}`

### AC-5: Migrations e validação

## Notas Técnicas

### Tabelas (resumo)

```sql
-- clientes: 1:1 com organizations
CREATE TABLE clientes (
  id uuid PK DEFAULT gen_random_uuid(),
  org_id uuid UNIQUE NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  cnpj text,
  setor text,
  porte text CHECK (porte IN ('micro','pequena','media','grande')),
  faturamento_faixa text,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

-- periodos_dados: 1 cliente → N períodos mensais
CREATE TABLE periodos_dados (
  id uuid PK DEFAULT gen_random_uuid(),
  cliente_id uuid NOT NULL REFERENCES clientes(id) ON DELETE CASCADE,
  mes int NOT NULL CHECK (mes BETWEEN 1 AND 12),
  ano int NOT NULL CHECK (ano >= 2024),
  status text NOT NULL DEFAULT 'em_coleta'
    CHECK (status IN ('em_coleta','pronto_para_analise','analisado','fechado')),
  closed_at timestamptz,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now(),
  UNIQUE (cliente_id, ano, mes)
);

-- colecoes: blocos de dado estruturados
CREATE TABLE colecoes (
  id uuid PK DEFAULT gen_random_uuid(),
  periodo_id uuid NOT NULL REFERENCES periodos_dados(id) ON DELETE CASCADE,
  tipo text NOT NULL CHECK (tipo IN ('formulario','texto_livre','transcricao_audio')),
  status text NOT NULL DEFAULT 'rascunho'
    CHECK (status IN ('rascunho','validado','descartado')),
  payload jsonb NOT NULL DEFAULT '{}'::jsonb,
  metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_by uuid REFERENCES profiles(id) ON DELETE SET NULL,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

-- evidencias: arquivos brutos
CREATE TABLE evidencias (
  id uuid PK DEFAULT gen_random_uuid(),
  periodo_id uuid NOT NULL REFERENCES periodos_dados(id) ON DELETE CASCADE,
  tipo text NOT NULL CHECK (tipo IN ('pdf','excel','csv','audio','outro')),
  storage_path text NOT NULL,
  nome_original text NOT NULL,
  mime_type text NOT NULL,
  tamanho_bytes bigint NOT NULL,
  hash text NOT NULL,
  transcricao text,
  transcricao_status text
    CHECK (transcricao_status IN ('pending','processing','completed','failed')),
  uploaded_by uuid REFERENCES profiles(id) ON DELETE SET NULL,
  created_at timestamptz DEFAULT now()
);
```

### RLS — padrão de policy

```sql
CREATE POLICY clientes_select ON public.clientes
  FOR SELECT USING (public.can_access_org(org_id));

CREATE POLICY clientes_insert ON public.clientes
  FOR INSERT WITH CHECK (public.has_org_role(org_id, 'client_owner'));

CREATE POLICY clientes_update ON public.clientes
  FOR UPDATE
  USING (public.can_access_org(org_id))
  WITH CHECK (public.can_access_org(org_id));
```

A propagação de `org_id` para `periodos_dados`, `colecoes` e `evidencias` é feita via subquery na policy, não via FK na policy. Exemplo:

```sql
CREATE POLICY periodos_select ON public.periodos_dados
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM clientes c WHERE c.id = periodos_dados.cliente_id AND public.can_access_org(c.org_id))
  );
```

### Storage bucket

```sql
INSERT INTO storage.buckets (id, name, public)
VALUES ('evidencias', 'evidencias', false);

-- Policy: membro da org pode ler
CREATE POLICY "evidencias_read" ON storage.objects
  FOR SELECT TO authenticated
  USING (
    bucket_id = 'evidencias'
    AND EXISTS (
      SELECT 1
      FROM public.evidencias e
      JOIN public.periodos_dados p ON p.id = e.periodo_id
      JOIN public.clientes c ON c.id = p.cliente_id
      WHERE e.storage_path = storage.objects.name
        AND public.can_access_org(c.org_id)
    )
  );
```

### Decisões técnicas

- **Cliente 1:1 com Organization**: separadas para que `clientes` carregue dados de negócio (CNPJ, setor, porte) sem poluir a tabela de tenants
- **Período UNIQUE (cliente_id, ano, mes)**: garante 1 período por mês por cliente
- **RLS via propagação**: políticas em `periodos_dados`, `colecoes`, `evidencias` usam `EXISTS` com JOIN em `clientes` para chegar no `org_id` e chamar `can_access_org()`
- **DELETE de coleções restrito a platform_admin**: clientes não podem deletar coleções (apenas mudar status para `descartado`)
- **Storage UPDATE bloqueado**: arquivos são imutáveis — correções exigem DELETE + INSERT
- **MIME allowlist no bucket**: PDFs, Excel, CSV e áudios comuns — o Storage aplica isso antes mesmo do RLS
- **Helper `list_periods_for_org`**: função SQL `SECURITY DEFINER` que faz JOIN com clientes para agregar contagens; RLS ainda aplicada porque policies em `periodos_dados` são respeitadas
