### Vitest config

```typescript
// vitest.config.ts
import { defineConfig } from "vitest/config";
import path from "path";

export default defineConfig({
  resolve: {
    alias: { "@": path.resolve(__dirname, "./src") },
  },
  test: {
    globals: true,
    environment: "node",
    include: ["tests/**/*.test.ts", "tests/**/*.test.tsx"],
    coverage: {
      provider: "v8",
      exclude: ["node_modules/", "tests/", "*.config.*", ".next/", ...]
```

### Decisões técnicas

- **Husky v9 + lint-staged:** setup mínimo (script `prepare` no package.json já roda `husky` automaticamente).
- **Vitest com @ alias:** o vitest config define alias explicitamente — não depende de tsconfig paths.
- **Coverage excludes:** pastas legadas (`aiox-core/`, `db/`, `supabase/`, `fluent forms/`, `api/`, `views/`) excluídas do coverage para focar no código Next.js.
- **Playwright webServer condicional:** em CI usa `npm run start` (production build); em dev usa `npm run dev` com `reuseExistingServer: true` para não travar o dev local.
- **Tempo de CI estimado:** quality-gates ~3min + unit-tests ~30s + e2e-tests ~2min = ~5-6min total por PR.
- **Deploy workflow:** usa Vercel CLI diretamente (não Vercel GitHub Action) para manter controle sobre as secrets.
