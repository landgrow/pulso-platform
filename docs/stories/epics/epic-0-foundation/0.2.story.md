## Descrição

Fluxo completo de autenticação: registro com confirmação de email, login, recuperação de senha (forgot/reset), e tratamento de edge cases (conta bloqueada, sessão expirada, rate limiting).

---

## Contexto

O PULSO usa Supabase Auth com email + senha. O frontend vanilla JS existente usa o Supabase Client diretamente no browser — esta story migra o auth para o padrão Next.js: **Server Actions** para operações sensíveis (registro, login, logout, reset) e **Auth Hook** para gerenciar estado da sessão no client. Middleware já existe e protege rotas autenticadas.

### Decisões técnicas

- **Server Actions vs client Supabase calls:** migrado de chamada direta no browser para Server Actions — validação server-side, melhor controle de rate limit e tratamento de erros.
- **Rate limit em memória:** adequado para single-instance (Vercel serverless cada lambda é um processo novo, mas a janela de 1min é curta o suficiente para mitigar abuso). Para produção com múltiplas instâncias, mover para Redis/Upstash — Story 0.7.
- **Forgot password sem revelar existência do email:** sempre retorna sucesso, mesmo se o email não existir no banco. Mensagem idêntica na tela.
- **Recovery via callback:** Supabase processa o token no `/auth/callback` quando o usuário clica no link, estabelece sessão temporária, redireciona para `/reset-password`. A sessão de recovery é automaticamente substituída quando o usuário salva a nova senha.
- **Mensagens de erro genéricas:** "Email ou senha incorretos" — não revela se o email existe ou se a senha está errada especificamente.
