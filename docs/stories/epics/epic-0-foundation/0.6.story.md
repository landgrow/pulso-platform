## Notas Técnicas

### Consentimento

```typescript
// registerConsent() chamada após signUp bem-sucedido
// Usa service_role para bypassar RLS no UPDATE do profile
async function registerConsent(userId: string): Promise<void> {
  const admin = await createAdminClient();
  await admin
    .from("profiles")
    .update({
      consent_version: "v1.0-2026-09-05",
      consent_timestamp: new Date().toISOString(),
    })
    .eq("id", userId);
}
```

### Audit Log

O audit log é lido da tabela `audit_log` criada na Story 0.3. A trigger `log_audit()` registra automaticamente INSERT/UPDATE/DELETE nas tabelas de organizations, memberships e profiles.

### Export de dados

O route handler `/api/data-export` gera um arquivo JSON para download. O conteúdo inclui: perfil do usuário, organizações vinculadas e metadados. O histórico de audit log completo é admin-only via a página dedicada.

### Decisões técnicas

- **HTML entities nos textos legais:** os textos de `/privacy` e `/terms` usam `&ldquo;` / `&rdquo;` para aspas em vez de caracteres crus — satisfaz a regra ESLint `react/no-unescaped-entities` sem precisar de comments.
- **Export via Route Handler (não Server Action):** Server Actions não suportam streaming de arquivo nativamente. O Route Handler `/api/data-export` é o endpoint correto para retornar um attachment com `Content-Disposition: attachment`.
- **Audit log admin-only:** a Server Action `getAuditLog` checa `is_platform_admin` no profile antes de retornar dados. A página exibe "Acesso negado" para não-admins.
- **Consentimento atômico com signUp:** o registro de consentimento é chamado logo após o `signUp` ser bem-sucedido. Se o registro de consentimento falhar, o usuário ainda é criado (degradação suave — o consentimento pode ser registrado depois).
