## Descrição

Implementar o **shell** — a estrutura visual que envolve todas as páginas autenticadas: sidebar navegável, header com perfil do usuário e tema toggle, e layout responsivo (desktop + mobile).

---

## Contexto

O PULSO usa um layout fixo para navegação interna. O shell é a moldura ao redor de todo conteúdo autenticado: barra lateral colapsável, header com avatar + dropdown de perfil, e área de conteúdo. O shell é um **layout de grupo** (`(dashboard)/`) que envolve todas as rotas autenticadas (`/dashboard/*`, `/colecoes/*`, `/bin/*`, `/programa/*`).

### Server vs Client Components no Shell

- `layout.tsx` → **Server Component** (verifica auth, busca dados do usuário)
- `sidebar.tsx` → **Client Component** (estado de colapso, tema, active route)
- `header.tsx` → **Client Component** (dropdown, tema)
- Navegação items → definir em `lib/constants.ts` para facilitar

### Decisões técnicas

- **Server Component no layout** — `getSession()` roda no servidor, evita expor user data no HTML. Middleware também checa, mas é uma camada adicional de defesa.
- **Sidebar como Client Component** — estado de colapso e pathname mudam dinamicamente; precisa de hooks.
- **Sheet via useSidebar** — o Sheet usa o mesmo context da sidebar para que o hamburger abra/feche corretamente.
- **Max-width no dashboard** — `max-w-6xl` para conteúdo principal; tabelas e listas usarão `max-w-full`.
- **Sign Out no header dropdown** — sai do header (não duplica na sidebar). User dropdown é a única entrada de sign out.
